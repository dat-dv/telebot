# Backend CRUD API

The REST CRUD surface covers transactions, debt contacts, debts, debt payments, reminders, allowlisted users/invites, Google Calendar events, and Google Tasks. It is a cross-cutting backend capability because the current API source has service folders rather than `src/modules/<feature>` feature directories.

Dashboard access tokens identify the caller. Local records are always scoped to that identity; user and invitation management requires the admin role. OAuth credentials and audit records are not exposed. Calendar and task operations act only on the caller's linked Google account.

Finance transactions support both single-item (`create_finance_transaction`) and multi-item batch creation (`create_finance_transactions`). A store, restaurant, or venue mentioned as `placeName` resolves or creates a caller-owned row in `finance_places` and binds `finance_transactions.place_id`; it never creates a debt contact. `/api/places` provides caller-scoped place CRUD. Debt payment is a dedicated action backed by `DebtPaymentEntity` (`debt_payments` table). Payment records store `debt_id`, `user_id`, `amount`, `payment_date`, and `note`. When recorded via `POST /api/debts/:id/payments`, a payment entry is saved, `remainingAmount` decreases, and when reduced to zero, the debt status transitions to `'settled'` with `settledAt` populated. Full repayment history is retrievable via `GET /api/debts/:id/payments`. Debts also support consolidation via `POST /api/debts/combine` linking child debts under a parent debt via `parent_debt_id`, and allocation from finance transactions via `POST /api/debts/allocations` (`debt_payment_allocations`). Contacts support `phoneNumber`, `bankAccountNumber`, `bankCode`, `bankName`, and `avatarUrl`. Finance transactions support `paymentMethod`, `currency`, `receiptUrl`, `contactId`, and optional `placeId`. Reminder entities track `status`, `snoozeCount`, `snoozedUntil`, and `completedAt`.
